### Совместный анализ клиентских баз с помощью SMPC

Банк хочет оценить и использовать данные телеком-оператора для скоринга, не обмениваясь клиентскими базами. Репозиторий — исследовательский прототип: протоколы приватного сопоставления на данных Home Credit, единый интерфейс для них и ML-часть (логистическая регрессия с приближённым градиентом, открыто и на CKKS).

## Что реализовано

| Уровень | Протокол / модуль | Банк узнаёт | Телеком узнаёт | Статус |
|---|---|---|---|---|
| 1 | PSI (OpenMined) | список общих ID | размер множества банка | готово |
| 1 | PSI-CA (OpenMined) | только число общих ID | размер множества банка | готово |
| 2 | PIS по бинам признака | N и сумма TARGET по бинам | какие его абоненты совпали | **прототип**, см. «Ограничения» |
| ML | Приближённая логистическая регрессия (открыто) | — | — | готово, `ml/approx.py` |
| ML | Тот же градиент над шифротекстами CKKS | — | — | прототип, нужен `[he]`, см. [docs/ckks_experiment.md](docs/ckks_experiment.md) |
| ML | Сравнение «банк» против «банк + телеком» | — | — | код готов, полный прогон не выполнен |
| — | Скоркарта на WoE из агрегатов PIS | — | — | заглушка |

Результат получает только банк. Модель противника — semi-honest (честный, но любопытный).

## Быстрый старт

1. Установить пакет (Python 3.10+). Для CKKS добавьте extra `he`:
   ```bash
   pip install -e ".[dev,he]"
   ```
2. Положить данные в папку `data/` (подробности в [data/README.md](data/README.md)):
   `bank_psi.parquet` и `telecom_train.parquet`. Для ML нужны все столбцы обоих файлов.
3. Запустить демо PSI, PSI-CA и PIS:
   ```bash
   python -m smpc --data-dir data
   ```
   Полезные параметры:
   - `--sample 50000` — случайная подвыборка у каждой стороны (по умолчанию полный объём);
   - `--feature DEF_30_CNT_SOCIAL_CIRCLE` — признак телекома для PIS;
   - `--protocols psi,psi_ca` — какие протоколы запускать;
   - `--verbose` — журнал сообщений между сторонами.
4. Сравнить «банк» и «банк + телеком» (ноутбук 05):
   ```bash
   smpc-compare --data-dir data --backends open --epochs 10
   smpc-compare --data-dir data --backends open,ckks --epochs 10 \
       --checkpoint-dir results/checkpoints --out results/compare.csv
   ```
   Команда печатает метрики, признаки телекома после L1 и прирост ROC-AUC и PR-AUC. С `--checkpoint-dir` обучение можно прервать и продолжить. Подробности и открытые вопросы: [docs/ckks_experiment.md](docs/ckks_experiment.md).
5. Запустить тесты (данные не нужны; тесты CKKS пропускаются без `tenseal`):
   ```bash
   pytest
   ```

Демо печатает сводку: результат каждого протокола, совпадение с эталоном (открытый JOIN), время, трафик, кто что узнаёт, а для PIS — таблицу WoE и IV.

## Как добавить протокол

1. Создать подкласс `smpc.protocols.base.Protocol`: задать `name`, `leakage` (кто что узнаёт) и метод `_execute(bank, telecom, channel)`.
2. Все сообщения между сторонами отправлять через `channel.send(...)` в байтах — тогда трафик посчитается сам.
3. Добавить класс в `REGISTRY` в `smpc/protocols/__init__.py` и сверку с эталоном в `smpc/demo.py`.
4. Написать тест на маленьком наборе из `tests/conftest.py`.

## Как добавить модель или градиент

* Модель: подкласс `smpc.ml.base.ScoringModel` (методы `fit` и `predict_proba`).
* Градиент для обучения: функция `gradient(w, b, X, y) -> (grad_w, grad_b)`, передаётся в `ApproxLogisticModel(gradient=...)`. Так устроен CKKS-вариант: `CKKSGradient` из `smpc.he.ckks`.
* Расшифрование агрегатов для CKKS: вызываемый объект, как `DemoAggregateDecryptor`. Настоящий протокол с распределённым ключом должен заменить именно его.

## Ограничения

- **PIS — прототип, а не защищённый протокол.** Сопоставление идёт по HMAC-псевдонимам с общим ключом, агрегаты считаются в открытую в доверенной демо-среде, Paillier шифрует только уже посчитанные итоги. Телеком видит, какие его абоненты совпали; при общем ключе каждая сторона может перебором восстановить ID другой. Агрегаты, WoE и IV при этом корректны.
- **CKKS-обучение — прототип.** Веса обновляются в открытом виде, L1-отбор признаков открытый, а агрегаты расшифровываются учебной заглушкой `DemoAggregateDecryptor`, которая видит значения. Вывод о защищённости схемы из этого сделать нельзя.
- **Отбор признаков для сравнения** выполняется на совместной матрице «банк + телеком». Модель «только банк» использует признаки, отобранные при наличии телекома. Вопрос, какую базу считать честной, открыт (см. [docs/ckks_experiment.md](docs/ckks_experiment.md)).
- **Утечки через агрегаты** возможны и у настоящего PIS: малые группы и повторные запросы могут выдать отдельных людей.
- **Обе стороны работают в одном процессе.** Для реального разделения доверия банк и телеком должны выполняться в разных окружениях.
- **Данные из одного набора Home Credit:** признаки «телекома» изначально собраны банком, разделение сторон моделируется. Общий ключ — `SK_ID_CURR`; в реальности им был бы, например, номер телефона.
